# TradingZero — PRD v-0.1.1

**Version:** 0.1.1
**Status:** Ready for Agent
**Date:** 2026-05-14

---

## Problem Statement

Dashboard TUI saat ini hanya menampilkan Sharpe ratio sebagai metrik utama, tanpa informasi tentang perilaku agent — apakah agent terlalu agresif BUY, terlalu pasif HOLD, atau aktif SELL. Pengguna tidak bisa membedakan apakah Sharpe tinggi karena strategi yang baik atau karena agent kebetulan Hold terus di uptrend. Selain itu, visualisasi Sharpe chart memiliki bug rendering (chart kosong saat semua nilai identik, dan layout tidak proporsional).

---

## Solution

Perluas dashboard TUI dengan:

1. **Action Distribution Panel** — panel di sebelah kanan chart Sharpe (split 80/20) yang menampilkan distribusi BUY/HOLD/SELL dari episode eval terakhir, last action agent, dan cumulative trade count sepanjang training.
2. **Win Rate tile** — tile baru di metrics bar yang menampilkan persentase episode yang profit (balance > initial balance).
3. **Bug fix chart** — perbaiki rendering chart saat semua nilai identik dan saat widget belum ter-resize.

---

## User Stories

1. As a trainer, I want to see the action distribution (% BUY/HOLD/SELL) from the latest eval episode, so that I can tell if the agent is learning a balanced strategy or collapsing to a single action.
2. As a trainer, I want to see the last action taken by the agent during eval, so that I can quickly assess the agent's current stance.
3. As a trainer, I want to see cumulative BUY and SELL counts across all training generations, so that I can track how active the agent has been over time.
4. As a trainer, I want to see win rate (% of eval episodes where final balance > initial balance), so that I can assess profitability beyond Sharpe ratio.
5. As a trainer, I want the Sharpe chart to render correctly even when all values are identical (e.g. all 0.0 at early training), so that the dashboard is usable from generation 1.
6. As a trainer, I want the Sharpe chart to occupy 80% of the chart area width and the action panel to occupy 20%, so that the chart remains the dominant visual element.
7. As a trainer, I want the action distribution to show a mini bar (e.g. `████░░`) next to each action percentage, so that I can scan the distribution at a glance.
8. As a trainer, I want the win rate tile to be color-coded (green ≥ 50%, red < 50%), so that I can immediately see if the agent is profitable.
9. As a trainer, I want cumulative trade counts to persist across generations (not reset per generation), so that I can see total training activity.
10. As a trainer, I want the action panel to update every generation alongside the chart, so that all panels stay in sync.

## Implementation Decisions

### Modules to modify

**1. `agent/trainer._evaluate`**
- Collect action counts per episode: count BUY (1), HOLD (0), SELL (2) across all steps across all eval episodes
- Compute win rate: count episodes where `final_balance > initial_balance` / `n_eval_episodes`
- Return new keys in eval dict: `action_counts` (dict with keys `buy`, `hold`, `sell`), `win_rate` (float 0–1)

**2. `agent/trainer.run`**
- Add cumulative counters: `self._cumulative_buys` and `self._cumulative_sells` (int, initialized to 0)
- After each `_evaluate`, add the episode action counts to cumulative counters
- Include `cumulative_buys` and `cumulative_sells` in `_notify` payload

**3. `tui/app.py — ChartPanel`**
- Fix flat-line rendering: when `hi == lo`, render a centered horizontal line with the value label
- Fix initial render: guard against `size.width == 0` or `size.height == 0` before calling `plt`

**4. `tui/app.py — ActionPanel` (new widget)**
- New `Static` subclass rendered as pure Rich markup
- Layout sections:
  - Action Distribution: label + Unicode bar + percentage for each of BUY, HOLD, SELL
  - Last Action: colored label (green=BUY, dim=HOLD, red=SELL)
  - Cumulative Trades: BUY count and SELL count
- Updates via `update_actions(payload: dict)` method
- Bar rendering: 6-char Unicode block bar proportional to percentage

**5. `tui/app.py — ChartArea` (new container)**
- Replace bare `ChartPanel` with a `Horizontal` container holding `ChartPanel` (80% width) and `ActionPanel` (20% width)

**6. `tui/app.py — MetricsBar`**
- Add `tile-winrate` MetricBox
- Color: green if win_rate ≥ 0.5, red otherwise

**7. `tui/app.py — TUIApp._handle_update`**
- Pass `action_counts`, `win_rate`, `cumulative_buys`, `cumulative_sells` from payload to ActionPanel and MetricsBar

### Payload contract (trainer → TUI)

```
{
  "generation": int,
  "current_sharpe": float,
  "best_sharpe": float,
  "promoted": bool,
  "total_generations": int,
  "final_balance": float,
  "pnl": float,
  "initial_balance": float,
  "win_rate": float,           # NEW — 0.0 to 1.0
  "action_counts": {           # NEW — from last eval
    "buy": int,
    "hold": int,
    "sell": int
  },
  "cumulative_buys": int,      # NEW — total across all gens
  "cumulative_sells": int      # NEW — total across all gens
}
```

## Testing Decisions

Good tests assert on **external behavior** — what the widget renders or what the payload contains — not on internal implementation details like private method calls.

### Modules to test

**`agent/trainer._evaluate`**
- Assert `win_rate` is 1.0 when all episodes are profitable
- Assert `win_rate` is 0.0 when all episodes lose money
- Assert `action_counts` keys exist and sum equals total steps across episodes
- Assert cumulative counters increment correctly across multiple `_evaluate` calls

**`tui/app.py — ActionPanel`**
- Assert `update_actions` does not raise with valid payload
- Assert rendered text contains "BUY", "HOLD", "SELL"
- Assert bar length is proportional to percentage (6 chars total)
- Assert last action label color matches action type

**`tui/app.py — ChartPanel`**
- Existing regression tests for flat-line (all zeros, all identical non-zero) must pass
- Assert chart renders without error when `size.width` and `size.height` are valid

**`tui/app.py — MetricsBar`**
- Assert `tile-winrate` exists after compose
- Assert win rate ≥ 0.5 renders with green style, < 0.5 with red

### Prior art
- Existing `test_metric_box_*` tests in `tests/unit/test_tui.py` — same pattern for ActionPanel
- Existing `test_chart_panel_all_zeros_does_not_raise` — extend for new edge cases

## Further Notes

- `ActionPanel` should degrade gracefully when payload does not yet contain `action_counts` (e.g. first generation before eval completes) — show "—" placeholders
- Win rate tile should be added between PnL and Promotions in the metrics bar
- Log line should include win rate: `win=80%` appended after pnl
- Cumulative counters live on the `Trainer` instance, not in the TUI — TUI is stateless for these values
