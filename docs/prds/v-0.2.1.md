# TradingZero — PRD v-0.2.1

**Version:** 0.2.1
**Status:** Draft
**Date:** 2026-05-14

---

## Problem Statement

Sebagai developer TradingZero, saya ingin mengganti total terminal dashboard (TUI) menjadi web app modern karena tampilan saat ini kurang nyaman untuk monitoring jangka panjang, investigasi crash, dan kontrol training dari satu tempat. Saya butuh observabilitas real-time, histori run yang persisten, serta kontrol start/stop/retry tanpa harus bergantung pada terminal UI.

---

## Solution

TradingZero akan melakukan cutover penuh dari TUI ke web app berbasis React (Vite) dengan backend Python FastAPI + WebSocket.

Solusi dari perspektif pengguna:
1. Menjalankan aplikasi via `main.py` tetap sama, tetapi output utama menjadi web dashboard.
2. Melihat metrik training real-time (Sharpe, Best Sharpe, Balance, PnL, Win Rate, Progress).
3. Melihat chart harga modern dengan marker Buy/Sell.
4. Melihat detail Last Action yang kaya konteks eksekusi (entry, size, notional, balance before/after, fee, dan state posisi).
5. Mengontrol lifecycle training dari browser (Start, Stop, Retry dari checkpoint terbaru).
6. Mengakses histori run dan error state setelah reload/crash browser karena data tersimpan di SQLite.

## Implementation Decisions

- Replace total dashboard: terminal TUI is retired as primary UI and web app becomes canonical monitoring/control surface.
- Backend runtime remains Python to preserve existing RL/training domain logic and reduce rewrite risk.
- Real-time transport uses WebSocket to support low-latency stream plus bidirectional control patterns.
- Persistence layer uses SQLite for runs, events, error logs, and configuration revisions.
- Schema migration uses Alembic to support forward/backward evolution safely.
- Data retention policy: keep run/event history for 90 days with scheduled prune.
- Single-user local operation for v0.2.1; no authentication/authorization added.
- Training concurrency limited to one active run; conflicting start request returns conflict response.
- Training control surface includes Start, Stop (graceful), Status, Retry from latest checkpoint.
- Existing checkpoint artifact format remains unchanged for backward compatibility with current inference flow.
- Entry point strategy: `main.py` transitions to web server startup path to enforce true replacement.
- Frontend stack direction: React + Vite with modern chart stack hybrid.
- Charting decision: TradingView Lightweight Charts for market/price visualization + Apache ECharts for dashboard analytics panels.
- Last Action domain object expanded to include execution context: action type, timestamp, price, size, pre/post position, notional, pre/post balance, fee, and unrealized PnL after action.
- Number formatting standard:
  - USD: grouped thousands with 2 decimals.
  - Price: symbol/tick-aware dynamic precision.
  - Percent: 2 decimals.
  - Signed PnL formatting explicit `+/-`.
- Time representation decision:
  - Default UTC in UI.
  - Optional toggle to local browser timezone.
- Error policy: fail visible + recoverable.
  - Status moves to error state.
  - Error metadata persisted and queryable per run.
  - UI provides explicit recovery path via retry.
- Observability scope (minimal approved set): plain logs + health endpoint.
- Delivery decomposition (internal execution plan):
  - Phase 1: backend web core, WebSocket stream, DB foundations.
  - Phase 2: frontend dashboard and control plane.
  - Phase 3: cutover cleanup, TUI removal, docs/tests hardening.
- Deep module strategy (testable, low-churn interfaces):
  - Run Orchestrator module: owns lifecycle transitions and single-run guard.
  - Event Stream module: maps trainer updates to typed outbound WebSocket events.
  - Run Repository module: persistence/read models for run timeline and error retrieval.
  - Config Service module: validated config revisions and active configuration snapshot.
  - Action Detail Mapper module: canonicalizes low-level trainer action data into rich Last Action payload for UI.

## Testing Decisions

- Good tests validate external behavior and contracts (status transitions, API responses, persisted records, rendered UI states), not implementation internals (private method structure, call counts of incidental helpers).
- Test coverage targets:
  - Backend unit tests for API contract, lifecycle state machine, WebSocket serialization envelope, single-run conflict behavior, retention pruning behavior.
  - Backend integration tests for full training lifecycle (start -> stream -> stop), retry flow, and error-path persistence.
  - Frontend component tests for metric cards, chart data plumbing, and detailed Last Action panel rendering.
  - End-to-end smoke test for operator journey: open app, start run, observe live updates, stop run, confirm status/history.
- Prior art in current codebase:
  - Existing unit and integration suites around environment, trainer, main flow, and TUI patterns provide baseline style and assertion philosophy.
  - Existing tests for runtime behavior (not internals) should be mirrored into web-era modules with equivalent behavior-first assertions.

## Out of Scope

- Multi-user accounts and authentication.
- Role-based access control.
- Distributed multi-run scheduler or cluster orchestration.
- Full observability stack (structured logging pipeline, metrics exporter, distributed tracing).
- Advanced strategy explainability (`reason_tag`) beyond optional future enhancement.
- Redesign of RL algorithm core or reward mechanics unrelated to dashboard migration.
- Cloud deployment automation and infrastructure-as-code.

## Further Notes
