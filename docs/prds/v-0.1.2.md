# TradingZero — PRD v-0.1.2

**Version:** 0.1.2
**Status:** Ready for Agent
**Date:** 2026-05-14
**Supersedes:** v-0.1.1 (replaces action panel design with 3-column layout)

---

## Problem Statement

Dashboard TUI saat ini hanya menampilkan Sharpe sparkline sebagai satu-satunya visualisasi, tanpa konteks harga aset atau perilaku agent. Pengguna tidak bisa melihat apakah agent buy/sell di timing yang tepat relatif terhadap pergerakan harga, dan tidak ada informasi distribusi action maupun win rate. RichLog terlalu tinggi sehingga chart area sempit.

---

## Solution

Redesign chart area menjadi 3 kolom:

1. **Kiri (40%)** — Sharpe sparkline history (seperti sekarang)
2. **Tengah (40%)** — Price chart dari episode eval terakhir dengan overlay action markers (▲ BUY hijau, ▼ SELL merah)
3. **Kanan (20%)** — Action stats panel: distribusi BUY/HOLD/SELL, last action, cumulative trades

Tambah tile **Win Rate** di metrics bar. Persempit RichLog ke height 4.

---

## User Stories

1. As a trainer, I want to see the price movement of the eval episode as a line chart, so that I can visually assess market conditions during evaluation.
2. As a trainer, I want BUY actions marked with ▲ (green) and SELL actions marked with ▼ (red) overlaid on the price chart, so that I can see if the agent times entries and exits well.
3. As a trainer, I want the Sharpe history sparkline to remain visible alongside the price chart, so that I can correlate price behavior with Sharpe trend.
4. As a trainer, I want to see action distribution (% BUY/HOLD/SELL) from the latest eval episode with a mini bar, so that I can detect action collapse (e.g. agent always HOLDs).
5. As a trainer, I want to see the last action taken by the agent during eval, so that I can quickly assess the agent's current stance.
6. As a trainer, I want to see cumulative BUY and SELL counts across all training generations, so that I can track total trading activity over time.
7. As a trainer, I want to see win rate (% of eval episodes where final balance > initial balance) as a tile in the metrics bar, so that I can assess profitability beyond Sharpe.
8. As a trainer, I want the win rate tile to be green when ≥ 50% and red when < 50%, so that I can scan it at a glance.
9. As a trainer, I want the RichLog to be 4 lines tall, so that the chart area has more vertical space.
10. As a trainer, I want all three chart panels to update every generation, so that everything stays in sync.
11. As a trainer, I want the action panel to show "—" placeholders before the first eval completes, so that the dashboard is usable from startup.
12. As a trainer, I want the log line to include win rate (e.g. `win=80%`), so that I can track it in the scrollable history.

## Implementation Decisions

### Layout

```
┌─ MetricsBar ──────────────────────────────────────────────────────────────────┐
│ Generation │ Progress │ Sharpe │ Best Sharpe │ Balance │ PnL │ WinRate │ Promotions │ Status │
└───────────────────────────────────────────────────────────────────────────────┘
┌─ Sharpe (40%) ──────┬─ Price + Action (40%) ──┬─ Action Stats (20%) ─────────┐
│                     │                          │                              │
│  Sharpe sparkline   │  65.9k ▁▂▃▄▅▆▇█         │  Action Distribution         │
│  (existing widget)  │  65.5k   ▲               │  BUY  ████░░  62%           │
│                     │  65.0k ████████           │  HOLD ██░░░░  28%           │
│                     │  64.5k ████▼████          │  SELL █░░░░░  10%           │
│                     │  64.0k ████████           │                              │
│                     │        ──────────         │  Last Action                 │
│                     │        step 1  step N     │  ▶ BUY                      │
│                     │                          │                              │
│                     │                          │  Cumulative Trades           │
│                     │                          │  BUY  : 1,243               │
│                     │                          │  SELL :   891               │
└─────────────────────┴──────────────────────────┴──────────────────────────────┘
┌─ RichLog (height: 4) ─────────────────────────────────────────────────────────┐
│ Gen 261 | sharpe=6.43 | best=18.35 | pnl=+$229.53 | win=80%                  │
└───────────────────────────────────────────────────────────────────────────────┘
```

### Modules to modify

**1. `agent/trainer._evaluate`**
- Collect per-step actions across all eval episodes into a flat list
- Compute `action_counts`: `{"buy": int, "hold": int, "sell": int}`
- Compute `win_rate`: episodes where `final_balance > initial_balance` / `n_eval_episodes`
- Collect price series from last eval episode: `close` prices at each step from `env.data`
- Return new keys: `action_counts`, `win_rate`, `price_series` (list[float]), `action_series` (list[int])

**2. `agent/trainer.run`**
- Add `self._cumulative_buys: int = 0` and `self._cumulative_sells: int = 0`
- After each `_evaluate`, increment cumulative counters from `action_counts`
- Include `cumulative_buys`, `cumulative_sells` in `_notify` payload

**3. `tui/app.py — PricePanel` (new widget)**
- New `Static` subclass
- Renders true line chart using `plotext` — same approach as `ChartPanel`
- `update_price(price_series: list[float], action_series: list[int])` method
- Uses `plt.plot()` for price line (cyan) and `plt.scatter()` with `▲`/`▼` markers for BUY/SELL
- BUY scatter: green `▲`; SELL scatter: red `▼`
- Uses `plt.plotsize(width, height)` to fit widget dimensions
- Respects widget size via `on_resize` — re-renders on terminal resize
- No `plt.title()` to avoid ghost rendering artifacts (same fix as ChartPanel)

**4. `tui/app.py — ActionPanel` (new widget)**
- New `Static` subclass
- Sections: Action Distribution (with 6-char Unicode bar), Last Action, Cumulative Trades
- `update_actions(payload: dict)` method
- Degrades gracefully: shows "—" when `action_counts` not in payload

**5. `tui/app.py — ChartArea` (new container)**
- Replace bare `ChartPanel` with `Horizontal` container:
  - `ChartPanel` — `width: 2fr` (40%)
  - `PricePanel` — `width: 2fr` (40%)
  - `ActionPanel` — `width: 1fr` (20%)

**6. `tui/app.py — MetricsBar`**
- Add `tile-winrate` between `tile-pnl` and `tile-promotions`
- Style: green border if win_rate ≥ 0.5, red border if < 0.5

**7. `tui/app.py — TUIApp`**
- `_handle_update`: route `price_series`, `action_series`, `action_counts`, `win_rate`, `cumulative_buys`, `cumulative_sells` to respective widgets
- Log line: append `win={win_rate*100:.0f}%`
- `RichLog height: 4`

### Payload contract (trainer → TUI)

```python
{
  "generation": int,
  "current_sharpe": float,
  "best_sharpe": float,
  "promoted": bool,
  "total_generations": int,
  "final_balance": float,
  "pnl": float,
  "initial_balance": float,
  "win_rate": float,            # 0.0–1.0
  "action_counts": {
    "buy": int,
    "hold": int,
    "sell": int
  },
  "price_series": list[float],  # close prices from last eval episode
  "action_series": list[int],   # 0/1/2 per step from last eval episode
  "cumulative_buys": int,
  "cumulative_sells": int
}
```

## Testing Decisions

Good tests assert on **external behavior** — rendered output, payload shape, widget state — not on internal method calls.

### Modules to test

**`agent/trainer._evaluate`**
- `win_rate == 1.0` when all episodes profitable
- `win_rate == 0.0` when all episodes lose
- `action_counts` keys exist and values sum to total steps
- `price_series` length equals `episode_length`
- `action_series` length equals `episode_length`
- Cumulative counters increment correctly across calls

**`tui/app.py — PricePanel`**
- `update_price` does not raise with valid data
- Single-point data shows placeholder
- Flat price data renders without error
- Resize triggers re-render without error

**`tui/app.py — ActionPanel`**
- `update_actions` does not raise with valid payload
- Missing `action_counts` in payload shows "—" placeholders
- Rendered text contains "BUY", "HOLD", "SELL"
- Bar length proportional to percentage (6 chars)

**`tui/app.py — MetricsBar`**
- `tile-winrate` exists after compose
- Win rate ≥ 0.5 renders green style
- Win rate < 0.5 renders red style

### Prior art
- `tests/unit/test_tui.py` — `test_metric_box_*`, `test_chart_panel_*` patterns apply directly

## Out of Scope

- Real-time price feed from exchange (live ticker)
- Candlestick (OHLC) chart — only close price line
- Per-step action replay animation
- Multi-episode price overlay
- Exporting chart to image

---

## Further Notes

- `price_series` and `action_series` come from the **last** eval episode only (not averaged across episodes)
- Price values should be raw close prices (not normalized) for readability
- `ChartPanel` existing bug fixes (flat-line, zero-size guard) remain in scope and should be verified
- `PricePanel` and `ChartPanel` share the same sparkline rendering logic — consider extracting a `_render_sparkline(data, markers, width, height)` helper to avoid duplication
