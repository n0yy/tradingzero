# TradingZero — PRD v-0.1.3

**Version:** 0.1.3
**Status:** Draft
**Date:** 2026-05-14

---

## Problem Statement

Agent saat ini hanya bisa masuk atau keluar posisi secara penuh (all-in / all-out). Ini membatasi kemampuan agent untuk belajar strategi yang lebih realistis seperti scale-in bertahap, partial exit, atau cut loss sebagian. Selain itu, observation space tidak memberi agent informasi tentang unrealized PnL dari posisi yang sedang dipegang, sehingga agent tidak bisa membedakan apakah posisi saat ini sedang profit atau rugi.

---

## Solution

1. **Ganti action space** dari `Discrete(3)` ke `MultiDiscrete([3, 4])` — direction (Hold/Buy/Sell) × size (25%/50%/75%/100%)
2. **Posisi additive** — Buy menambah posisi, Sell mengurangi posisi, keduanya di-clamp ke [0.0, 1.0]
3. **Perluas observation space** dari `(60, 6)` ke `(60, 7)` — tambah channel unrealized PnL (normalized)
4. **Arsipkan checkpoint lama** ke `agent/checkpoints/archive/` sebelum training ulang

---

## User Stories

1. As a trainer, I want the agent to choose both direction (Buy/Sell/Hold) and size (25%/50%/75%/100%) independently, so that it can learn position sizing as part of its strategy.
2. As a trainer, I want Buy actions to additively increase position (capped at 100%), so that the agent can scale into a position gradually.
3. As a trainer, I want Sell actions to additively decrease position (floored at 0%), so that the agent can scale out of a position gradually.
4. As a trainer, I want transaction cost to be charged on every position change regardless of size, so that the agent is discouraged from overtrading.
5. As a trainer, I want the observation to include unrealized PnL as a normalized channel, so that the agent knows whether its current position is profitable.
6. As a trainer, I want old checkpoints archived (not deleted), so that I can compare old vs new agent performance later.
7. As a trainer, I want the Hold action to ignore the size axis entirely, so that the agent doesn't waste capacity learning that Hold+25% == Hold+100%.
8. As a trainer, I want position size to be visible in the observation, so that the agent knows how exposed it currently is.

## Implementation Decisions

### Action Space

```
MultiDiscrete([3, 4])
  axis 0 — direction: 0=Hold, 1=Buy, 2=Sell
  axis 1 — size:      0=25%, 1=50%, 2=75%, 3=100%
```

Size axis is ignored when direction=Hold.

### Position Update Logic

```
size_map = {0: 0.25, 1: 0.50, 2: 0.75, 3: 1.00}
delta = size_map[size_action]

if direction == 1 (Buy):
    new_position = min(current_position + delta, 1.0)
    traded = new_position - current_position  # actual change
elif direction == 2 (Sell):
    new_position = max(current_position - delta, 0.0)
    traded = current_position - new_position  # actual change
else:
    new_position = current_position
    traded = 0.0

cost = transaction_cost * traded  # proportional to actual change
```

### Observation Space

```
Shape: (60, 7)  — was (60, 6)
Channels: [open, high, low, close, volume, position, unrealized_pnl]

position: float in [0.0, 1.0] — current position size
unrealized_pnl: float, normalized by initial_balance
  = (current_price - avg_entry_price) * position / initial_balance
  = 0.0 when position == 0.0
```

Agent tracks `avg_entry_price` — updated on every Buy using weighted average:
```
avg_entry_price = (prev_avg * prev_position + current_price * traded) / new_position
```
Reset to 0.0 when position reaches 0.0.

### Reward Function

Unchanged — Sharpe ratio of rolling step returns + immediate price return signal. Step return now reflects partial position:
```
step_return = price_return * position - cost
```

### Checkpoint Migration

- Move existing `agent/checkpoints/*.zip` to `agent/checkpoints/archive/`
- New training starts from scratch with new action/observation space
- `run_best.py` should detect incompatible checkpoints and warn the user

## Testing Decisions

Good tests assert on **external behavior** — position values, cost deductions, obs shape — not internal method calls.

### Modules to test

**`env/crypto_env.py`**
- `action_space` is `MultiDiscrete([3, 4])`
- `observation_space.shape == (window_size, 7)`
- Buy 25% from 0.0 → position == 0.25
- Buy 50% from 0.75 → position == 1.0 (capped)
- Sell 25% from 0.50 → position == 0.25
- Sell 100% from 0.25 → position == 0.0 (floored)
- Hold → position unchanged regardless of size axis
- Transaction cost charged proportional to actual position change
- No cost charged on Hold
- Unrealized PnL channel is 0.0 when position == 0.0
- Unrealized PnL channel reflects correct value when position > 0.0
- `avg_entry_price` resets to 0.0 after full sell
- `obs.shape == (window_size, 7)` after reset and after step
- Reward is finite for all valid action combinations

### Prior art
- `tests/unit/test_env.py` — existing env tests, extend with new action/obs cases
- `tests/unit/test_tui.py` — `test_chart_panel_*` pattern for any TUI display of sizing

---

## Out of Scope

- Continuous action space (Box)
- Leverage / margin trading
- Short selling (position floored at 0.0, not negative)
- Multi-asset portfolio sizing
- Kelly criterion or other position sizing formulas as reward shaping

---

## Further Notes

- SB3 PPO supports `MultiDiscrete` natively — no custom policy needed
- `gymnasium.utils.check_env()` should pass after changes
- Old checkpoints in `archive/` are incompatible with new env — do not load them with new env without re-training
- `window_size` stays at 60 — only the feature dimension changes from 6 to 7
