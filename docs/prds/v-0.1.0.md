# TradingZero — Product Requirements Document

**Version:** 1.0  
**Status:** Draft  
**Inspiration:** AlphaZero (Self-Play RL)  
**Target Market:** Crypto (BTC/ETH/Altcoins)

---

## 1. Visi Produk

TradingZero adalah sistem trading berbasis Reinforcement Learning yang belajar strategi crypto murni dari self-play — tanpa indikator teknikal buatan manusia. Agent berevolusi dengan cara mengalahkan versi dirinya sendiri dari episode sebelumnya, menghasilkan strategi adaptif yang semakin tajam dari waktu ke waktu.

---

## 2. Tujuan

- Implementasi self-play loop yang stabil dan reproducible
- Agent mampu belajar kapan harus Buy, Hold, atau Sell dari raw OHLCV data
- Semua progress training dapat dipantau secara real-time via TUI
- Codebase dibangun dengan pendekatan TDD dari hari pertama

---

## 3. Scope

**In Scope:**
- Custom Gymnasium environment untuk crypto
- PPO agent dengan self-play curriculum
- TUI real-time monitoring (Textual + Rich + Plotext)
- Data pipeline dari exchange via CCXT
- Test suite lengkap (unit + integration)

**Out of Scope (v1):**
- Live trading / paper trading ke exchange nyata
- MCTS (dipertimbangkan untuk v2)
- Multi-asset portfolio
- Web dashboard

## 6. Komponen Detail

### 6.1 Data Layer (`data/fetcher.py`)

**Tanggung Jawab:**
- Fetch OHLCV dari exchange via **CCXT**
- Normalisasi & windowing data dengan **Pandas** dan **NumPy**
- Cache data lokal untuk reproducibility training

**Output:** DataFrame OHLCV yang siap dikonsumsi environment

```
Columns: [timestamp, open, high, low, close, volume]
Window: 60 candle per observasi
Normalisasi: min-max per window
```

### 6.2 Environment (`env/crypto_env.py`)

**Library:** Gymnasium  
**Base Class:** `gym.Env`

**State Space:**
```
Shape: (60, 6)  → 60 candle × [O, H, L, C, V, position]
dtype: float32
Range: [0, 1] setelah normalisasi
```

**Action Space:**
```
Discrete(3)
  0 = Hold
  1 = Buy (full position)
  2 = Sell (close position)
```

**Reward Function:**
```
reward = sharpe_ratio(returns, window=20)
penalty = -0.001 per trade (transaction cost simulation)
```

**Episode:**
```
Start: random offset dalam data training
End: 500 langkah atau saldo habis
```

### 6.3 Agent & Self-Play (`agent/trainer.py`)

**Library:** Stable-Baselines3 (PPO) + PyTorch

**Self-Play Curriculum:**
```
1. Inisialisasi agent random (generation 0)
2. Jalankan N episode → simpan replay & metrics
3. Hitung mean Sharpe ratio episode ini
4. Bandingkan dengan best_checkpoint Sharpe ratio
5. Jika lebih baik → promote ke best_checkpoint
6. Ulangi dari step 2
```

**PPO Hyperparameters (default):**
```
learning_rate:    3e-4
n_steps:          2048
batch_size:       64
n_epochs:         10
clip_range:       0.2   ← ini yang bikin PPO "proximal"
gamma:            0.99
gae_lambda:       0.95
```

**Checkpoint Strategy:**
```
Simpan setiap 10 generasi
Format: checkpoints/gen_{N}_sharpe_{score}.zip
Best checkpoint selalu di: checkpoints/best.zip
```

### 6.4 TUI Monitor (`tui/app.py`)

**Library:** Textual + Rich + Plotext

**Layout:**
```
┌─ TradingZero ──────────────────────────────────────────┐
│  Generation: 142    Best Sharpe: 1.84    Status: TRAIN  │
├──────────────────────────┬─────────────────────────────┤
│  Equity Curve (Plotext)  │  Training Log (Rich)        │
│                          │                             │
│  ▲  10,450               │  [142] reward: +0.032       │
│  │       ╭──╮            │  [142] action: BUY @ 43,210 │
│  │──────╯  ╰────╮        │  [141] ✓ promoted to best   │
│  └─────────────────      │  [140] reward: -0.011       │
├──────────────────────────┴─────────────────────────────┤
│  Metrics Panel (Rich Table)                            │
│  Policy Loss: 0.021  │  Value Loss: 0.043  │  LR: 3e-4 │
│  Win Rate:    58.3%  │  Max DD: -12.4%     │  Gen: 142  │
└────────────────────────────────────────────────────────┘
```

**Update Frequency:** Real-time per step via Textual reactive state

## 8. Development Process: Test-Driven Development (TDD)

### 8.1 Filosofi

TradingZero dibangun dengan **TDD ketat (Red → Green → Refactor)**. Setiap komponen ditulis tesnya terlebih dahulu sebelum implementasi. Ini krusial untuk sistem RL karena bug di environment atau reward function bisa sangat silent namun merusak training.

### 8.2 Siklus TDD per Komponen

```
1. RED   → Tulis test yang gagal dulu
2. GREEN → Tulis kode minimal agar test lulus
3. REFACTOR → Bersihkan kode tanpa ubah behavior
```

**Contoh siklus untuk `crypto_env.py`:**

```python
# STEP 1: RED — tulis test dulu (test_env.py)
def test_reset_returns_valid_observation():
    env = CryptoEnv(data=mock_ohlcv)
    obs, info = env.reset()
    assert obs.shape == (60, 6)
    assert obs.dtype == np.float32
    assert 0.0 <= obs.min() and obs.max() <= 1.0

# STEP 2: GREEN — implement minimal di crypto_env.py
# STEP 3: REFACTOR — bersihkan setelah hijau
```

### 8.3 Test Layers

#### Unit Tests (`tests/unit/`) — via Pytest + pytest-mock

Setiap fungsi ditest secara isolasi. External dependencies di-mock dengan **pytest-mock**.

| File Test | Yang Ditest |
|---|---|
| `test_fetcher.py` | Parsing OHLCV, normalisasi, windowing |
| `test_env.py` | Reset, step, reward, done condition |
| `test_trainer.py` | Checkpoint logic, self-play promotion |

```python
# Contoh mock CCXT di test_fetcher.py (pytest-mock)
def test_fetch_ohlcv(mocker):
    mock_exchange = mocker.patch("ccxt.binance")
    mock_exchange.return_value.fetch_ohlcv.return_value = MOCK_DATA
    result = fetch_ohlcv("BTC/USDT", "1h", limit=100)
    assert len(result) == 100
```

#### Property-Based Tests — via Hypothesis

Digunakan untuk environment edge cases yang sulit dipikirkan secara manual.

```python
# Contoh property test untuk reward function
@given(st.floats(min_value=-1.0, max_value=10.0))
def test_reward_always_finite(return_value):
    reward = compute_reward(return_value)
    assert np.isfinite(reward)
```

#### Integration Tests (`tests/integration/`) — via Pytest

Test end-to-end satu training loop pendek (10 episode) untuk memastikan semua komponen bekerja bersama.

```python
def test_one_training_cycle_completes():
    env = CryptoEnv(data=mock_data)
    trainer = Trainer(env, total_episodes=10)
    trainer.run()
    assert trainer.best_sharpe > -np.inf
    assert Path("checkpoints/best.zip").exists()
```

## 11. Risiko & Mitigasi

| Risiko | Dampak | Mitigasi |
|---|---|---|
| Reward NaN karena data anomali | Training crash | Test dengan Hypothesis, clamp reward |
| Overfitting ke data historis | False Sharpe tinggi | Walk-forward validation, held-out test set |
| CCXT API rate limit | Data fetch gagal | Cache lokal wajib, retry logic |
| Textual blocking training loop | TUI freeze | Run training di thread terpisah |
| Checkpoint korup | Progress hilang | Validasi setelah save, backup best 3 |

## 12. Glossary

| Term | Definisi |
|---|---|
| **Episode** | Satu sesi trading dari awal sampai akhir data atau saldo habis |
| **Generation** | Satu iterasi self-play (kumpulkan pengalaman → update → compare) |
| **Best Checkpoint** | Model dengan Sharpe ratio tertinggi yang pernah dicapai |
| **Promote** | Proses mengganti best checkpoint dengan model yang lebih baik |
| **Sharpe Ratio** | Metrik return vs risiko — makin tinggi makin baik |
| **Policy** | Keputusan agent: given state, pilih action dengan probabilitas berapa |
| **PPO** | Proximal Policy Optimization — algoritma RL yang dipakai |

## 11. Risiko & Mitigasi

| Risiko | Dampak | Mitigasi |
|---|---|---|
| Reward NaN karena data anomali | Training crash | Test dengan Hypothesis, clamp reward |
| Overfitting ke data historis | False Sharpe tinggi | Walk-forward validation, held-out test set |
| CCXT API rate limit | Data fetch gagal | Cache lokal wajib, retry logic |
| Textual blocking training loop | TUI freeze | Run training di thread terpisah |
| Checkpoint korup | Progress hilang | Validasi setelah save, backup best 3 |

## 12. Glossary

| Term | Definisi |
|---|---|
| **Episode** | Satu sesi trading dari awal sampai akhir data atau saldo habis |
| **Generation** | Satu iterasi self-play (kumpulkan pengalaman → update → compare) |
| **Best Checkpoint** | Model dengan Sharpe ratio tertinggi yang pernah dicapai |
| **Promote** | Proses mengganti best checkpoint dengan model yang lebih baik |
| **Sharpe Ratio** | Metrik return vs risiko — makin tinggi makin baik |
| **Policy** | Keputusan agent: given state, pilih action dengan probabilitas berapa |
| **PPO** | Proximal Policy Optimization — algoritma RL yang dipakai |
| **OHLCV** | Open, High, Low, Close, Volume — format data candle standar |
