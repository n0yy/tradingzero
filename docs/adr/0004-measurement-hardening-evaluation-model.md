# Measurement hardening uses a fixed out-of-sample evaluation model

The current trainer learns and evaluates on episodes sampled from the same dataset, which makes early Sharpe improvements too easy to over-trust. We decided that each Run uses separate **Training Slice** and **Evaluation Slice** data: the Evaluation Slice is one fixed chronological holdout block, read-only for evaluation, and every Generation is tested by the same deterministic **Evaluation Pass** made from evenly spaced fixed **Evaluation Anchors**. Checkpoint promotion is driven by **Evaluation Sharpe** rather than Training Sharpe, with a simple **Promotion Gate** that also requires minimum Executed Trade count and minimum SELL-side realized exits. To keep the result auditable and replayable, each Run persists its **Evaluation Spec** and both Training/Evaluation seeds, and each Generation persists an **Evaluation Record** with per-anchor detail and human-readable pass/fail reasons.
